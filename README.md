# Task Service

REST API для управления задачами с поддержкой **периодической активации задач**.

---

# Что было реализовано

В существующий сервис добавлена возможность:

* задавать периодичность задачи
* автоматически изменять её активность
* повторно публиковать завершённые задачи
* выполнять пересчёт:

  * при запуске приложения
  * ежедневно по расписанию

---

# Принятый подход

Вместо создания новых записей по расписанию каждая задача хранит:

| поле                | назначение               |
| ------------------- | ------------------------ |
| `is_active`         | активна ли задача сейчас |
| `periodicity_type`  | тип расписания           |
| `periodicity_value` | параметр расписания      |
| `publish_date`      | дата начала действия     |

Задача рассматривается как:

```text
не одноразовая запись,
а правило её доступности
```

Это позволило встроить функциональность без полного изменения существующей модели.

---


# Как работает активация

При запуске scheduler вызывает:

```go
UpdateActivity()
```

Метод:

1. получает задачи из Базы
2. вычисляет должна ли задача быть активной
3. сравнивает текущее состояние
4. обновляет только изменившиеся задачи

---

# Поведение завершённых задач

Если задача:

```text
status = done
```

и наступает новый период:

то статус автоматически переводится в:

```text
status = new
```

Это позволяет использовать одну и ту же задачу повторно.

---

# Планировщик

Используется:

`gocron`

Запуск происходит:

* сразу после старта приложения
* каждый день в заданное локальное время

Это позволяет:

* восстановить состояние после перезапуска
* поддерживать актуальность без ручного запуска

---

# Учтённые граничные случаи

## Перезапуск приложения

Если приложение было выключено в момент планового запуска:

```text
UpdateActivity()
```

выполняется сразу после старта.

---

## Повторное обновление

Обновление выполняется только если изменилось:

```text
is_active
```

Это уменьшает количество лишних UPDATE запросов.

---

## Завершённая задача

Если задача была завершена, но период наступил снова:

```text
done -> new
```
